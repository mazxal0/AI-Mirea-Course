## 5. Экспериментальный протокол и результаты

**5.1. Протокол экспериментов**  
- Данные: датасет RuPAWS (8 814 пар, бинарная метка).  
- Разделение выборки: 80% / 20% (train / test) со стратификацией по метке.  
- Метрики: Accuracy, F1-score (класс 1), Precision, Recall.  
- Оценка проводилась на отложенной тестовой выборке (20%).  

**5.2. Сравнение моделей по метрикам**  

| Модель | Accuracy | F1 (class 1) | Precision | Recall |
|--------|----------|--------------|-----------|--------|
| RandomForest (baseline) | 0.66 | 0.49 | 0.58 | 0.43 |
| Bi-Encoder (без дообучения) | 0.56 | 0.58 | 0.46 | 0.77 |
| Bi-Encoder (дообученный) | 0.69 | 0.65 | 0.57 | 0.76 |
| **Cross-Encoder (финальная модель)** | **0.77** | **0.71** | **0.70** | **0.71** |

**5.3. Выбор финальной модели**  
Финальной выбрана **дообученная Cross-Encoder** модель, так как она показывает наилучший баланс точности и полноты (F1 = 0.71) и высокую общую точность (77%). При умеренном увеличении времени инференса она даёт выигрыш в качестве на сложных адверсариальных примерах (перестановка слов, отрицания).

## 6. Архитектура решения и сервис

**6.1. Архитектура пайплайна**  
1. Загрузка данных (RuPAWS) → EDA и предобработка в ноутбуках.  
2. Обучение моделей (RandomForest, Bi-Encoder, Cross-Encoder) – ноутбуки `notebooks/exp*.ipynb`.  
3. Выбрана лучшая модель (Cross-Encoder) → экспорт в `artifacts/`.  
4. FastAPI-сервис (`src/service.py`) загружает модель и предоставляет REST API.  
5. Логирование (`logger_config.py`), конфигурация через `.env`.  
6. Контейнеризация через Docker, тестирование через `pytest`.

**6.2. API и endpoints**  
- `GET /api/v1/health` – проверка работоспособности сервиса.  
- `POST /api/v1/predict` – принимает JSON `{"text_a": "...", "text_b": "..."}`.  
  **Ответ:** `{ "text_a": "...", "text_b": "...", "probability": float, "label": 0/1, "verdict": "Same/not same" }`.

**6.3. Технологический стек**  
- FastAPI, Uvicorn, Python-dotenv, Pydantic.  
- Sentence-Transformers, PyTorch, Transformers.  
- Docker, Docker Compose, Pytest.  
- Логирование через `logging` (консоль + файл `logs/app.log`).

## 7. Наблюдаемость, конфигурация и безопасность

**7.1. Логи и наблюдаемость**  
- Все запросы к `/predict` логируются (уровень INFO – текст, предсказанная вероятность, вердикт).

- Шаблон `.env.example` в репозитории (MODEL_PATH, DEVICE, THRESHOLD, LOG_LEVEL).  
- Настройки можно изменять без правки кода.

**7.3. Безопасность**  
- Файл `.env` добавлен в `.gitignore`.  
- В репозитории отсутствуют секреты (токены, пароли).  
- Docker-образ не содержит чувствительных данных, все конфигурации передаются через окружение.

## 8. Ограничения и дальнейшая работа

**Текущие ограничения**  
- Датасет RuPAWS имеет сравнительно небольшой размер (8.8k пар) и недостаточно примеров с синонимическими заменами.  
- Обучение проводилось на CPU из-за ограниченных ресурсов, что не позволило увеличить число эпох и размер батча.  
- Модель не всегда корректно обрабатывает короткие противоположные высказывания («Да» / «Нет»).  

**Направления развития**  
- Расширить датасет примерами с синонимами, отрицаниями, разными стилями текстов.  
- Выполнить дообучение на GPU (например, в Colab Pro) с большим числом эпох и подбором гиперпараметров.  
- Добавить полноценный frontend (Gradio/Streamlit) и дополнительные эндпоинты (например, `/compare` для сравнения двух моделей).  
- Реализовать кэширование результатов и асинхронную обработку длинных текстов.
